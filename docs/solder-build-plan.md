## 2. What Solder is (one line each)
1. **Idea → build**: type an idea → parts list with INR prices, 3D-printable case (STL, assembled/exploded, burst reveal), Fritzing-style wiring with Simulate toggle, Arduino code.
2. **Solder Agent**: compiles the code, simulates it, catches a bug, patches, re-tests, checks case fit — shown live as a log.
3. **Order it**: cart of parts + nearest 3D print shop (estimates, example names clearly labelled).
4. **Ship it**: product name, product page, box design.
5. **AR "view on your desk"**: `<model-viewer>` with GLB (Android) / USDZ (iOS) via QR.
6. **Change-it chips**: "solar powered", "smaller", "add WiFi" → regenerates.

## 3. Why we win — gap vs prior art + 5 standout features
Gap: Flux is a pro EDA tool (PCB-first, for engineers). Zoo/CADAM do only the case. Text to Chip does only wiring + code on 3 boards. **Nobody goes idea → code that really runs → case that really fits → a product you can buy parts for, made for a beginner in India with INR prices, in one screen.**

Standout features (all buildable by ~11 AM, ordered by impact/effort):
1. **Real code, really running, in your browser.** Server compiles the Arduino sketch with `arduino-cli` (Uno target) → `.hex`; browser runs it with **avr8js** (Wokwi's open-source AVR simulator, MIT) with virtual sensor sliders (soil %, temperature, button) and the LED/pump reacting. The Agent's self-fix loop uses *real* compiler errors and simulated serial output, not a fake animation. (ESP32 builds: compile-check only, mark "sim: Uno variant".)
2. **Scrap mode / Photo to build.** Snap a photo of the parts drawer → Gemini vision lists what you own → build reuses them and only buys the rest ("you save ₹640"). None of the tools above do this.
3. **Fit check that's real.** Parts come from a small JSON library with real dimensions (Uno 68.6×53.4 mm, SG90, relay module, OLED 0.96", soil probe, 18650 holder...). OpenSCAD case is generated *around* those boxes; server checks clearance and shows "Fits ✓ 2.0 mm" or the Agent fixes the wall.
4. **Flash it to a real board.** "Plug in and flash" button using WebSerial (avrgirl-arduino for Uno or ESP Web Tools for ESP32). Needs HTTPS + Chrome. Stretch goal — if Archit has an Uno at home, this is the killer shot for the video.
5. **Share / remix link.** Every build gets a public URL (`/b/sip`) with the burst animation as preview — viewers of the YouTube video can open and remix Sip/Wisp/Hasp/Eave. Drives engagement score.
(Cut if short on time: AR, Order it map. Never cut 1 and the Agent loop.)

```
 ├─ Agent log panel (streamed steps via SSE)
 ├─ Order / Ship / AR tabs  (<model-viewer> for AR)
 └─ WebSerial flash (stretch)
        │  HTTPS (Caddy, auto Let's Encrypt)
Node/Express API on VM 159.223.154.151 (Docker, own port, do NOT touch the DCN closer)
 ├─ POST /api/build      → Gemini 3.8 Flash (JSON schema) → validate (zod)
 ├─ POST /api/scad       → openscad CLI → STL  (+ trimesh/gltf-transform → GLB/USDZ optional)
 ├─ POST /api/compile    → arduino-cli compile --fqbn arduino:avr:uno → .hex or errors
 ├─ POST /api/fix        → Flash-Lite with errors/sim log → patched code/scad
 ├─ POST /api/photo      → Gemini vision (Flash) → owned-parts list
 ├─ GET  /api/showcase/:id → cached JSON
 └─ cache/  (prompt-hash → result), rate limiter
```
Domain without buying one: `https://solder.159-223-154-151.sslip.io` (sslip.io resolves to the IP; Caddy gets a cert). HTTPS is needed for camera + WebSerial.

**Gemini calls (outline)**
1. `build` — model `gemini-3.8-flash`, `responseMimeType: application/json`, `responseSchema`:
   ```
   { name, tagline, summary,
     board: "uno"|"esp32",
     parts: [{id, name, libId, qty, priceInr, why}],
     layout: [{libId, x, y, z, rotZ}],          // mm, inside case
     case: {scad, wallMm, lidType, outerMm:[x,y,z]},
     wiring: [{from:{part,pin}, to:{part,pin}, color, signal}],
     code: {filename, ino},
     tests: [{name, set:{sensor:value}, expectSerial|expectPin}],
     product: {pageHeadline, bullets[], priceInr, boxSvg},
     buildSteps: [string] }
   ```
   System prompt: "You are Solder, a hardware engineer for beginners in India. Only use parts from this library (JSON attached). Prices are rough INR estimates. Case must be printable without supports, 2 mm walls, 1.5–2 mm clearance around every part. Code must compile for {board} with only these libraries: Servo, Wire, Adafruit_SSD1306, DHT. Include Serial prints that the tests can assert."
2. `fix` — `gemini-3.5-flash-lite`, input = previous code/scad + compiler error or failed test + sim serial log, output `{diagnosis, patch:{ino?|scad?}, changelog}`.
3. `photo` — `gemini-3.8-flash` with image, output `{owned:[{libId, qty, confidence}]}`.
4. `change` — chip text + previous JSON → same schema (Flash-Lite).

**Agent loop (what judges watch)**: generate → compile → (errors? fix, max 2) → run each test in avr8js headless (node) → (fail? fix) → scad → STL → fit check → (collision? fix) → done. Every step streams to the Agent log with ✓/✗.

**Burst reveal**: three.js — each part is its own mesh; on load, parts start scattered + rotated, ease (slow-mo) into exploded positions, hold, then snap to assembled while the camera dollies back (matches the Pi 5 reference). Same code drives all 4 products since it reads the `layout`.
